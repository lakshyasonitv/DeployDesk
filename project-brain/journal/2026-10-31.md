### Problems hit & how fixed

- **The two verify failures are seed age, not data loss.** `SEED_NOW` defaults to
  `new Date()` at seed time (`src/db/seed/helpers.ts:16`), and fixture `last_confirmed_at`
  values are offsets from it. `freshnessFor` compares against the real now. About 23 days after
  the 2026-10-08 seed, every profile is past the window. **Unconfirmed people fail the matching
  staleness gate**, so the vendor dashboard reads 0 confirmed / 42 unconfirmed, and **"Re-run
  matching" today would likely drop most candidates**. The matching desk still shows its 17
  because those rows were scored at seed time. **Not fixed:** `npm run db:seed` fixes it but
  WRITES to Supabase, so it waits for the owner (rule 1).
  This will recur every time the demo sits idle for more than about two weeks, which makes
  `30/30` a gate that depends on the date. Worth knowing before trusting it as one.
- **Layout defect found:** at about 800 px viewport width the header breadcrumb ("Overview")
  overprints the "DEMO · Acting as" organisation switcher. It is fine at 1366 px. Not fixed.
