### Problems hit & how fixed

- **`CLAUDE.md` points at paths that do not exist.** It routes every doc reference through
  `docs/` — `docs/MASKING.md`, `docs/ARCHITECTURE.md`, `docs/DOMAIN.md` — but all eleven
  files sit at the repo root. A session following CLAUDE.md literally cannot find
  `docs/MASKING.md`, which CLAUDE.md itself calls mandatory before touching any read path.
  Recorded as a Gotcha in `01-architecture.md` and queued as a task. **Deliberately not
  fixed** — whether to create `docs/` or correct the references is the user's call, and it
  was outside what `/brain init` was asked to do.

- **Considered fully pre-filling the brain from the docs, and rejected it.** Mirroring the
  ten ADRs into `02-decisions.md` and the layer map into `01-architecture.md` reads well on
  day one, but `CLAUDE.md` explicitly says "do not duplicate content between them — link
  instead", and a copied ADR diverges the moment one is superseded. Kept the brain thin;
  the only genuinely new content is the Gotchas section, progress, tasks and this journal.

- **The Obsidian junction needed PowerShell, not Bash.** `New-Item -ItemType Junction` has
  no clean Git Bash equivalent here: `cmd /c mklink /J` hits MSYS path mangling, and the
  vault path contains both a space and an apostrophe. Verified `.obsidian` lives in the
  **inner** `Lakshya's Thinking` folder (the outer one is just a wrapper and Obsidian reads
  nothing from it) before creating the junction there.

- **Not a git repo**, so the usual "commit `project-brain/`" step does not apply yet. Left
  as a Phase 0 task: `git init` and commit the docs plus the brain *before* any code lands.
